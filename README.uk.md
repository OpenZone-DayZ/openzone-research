# OpenZone Research

*[In English](README.md)*

Бали досліджень і дерево технологій для серверів OpenZone, на ядрі OpenZone.

**Стан: перший випуск після `ZP_Research`.** Правила гри -- ті самі, що в ZP_Research;
код новий і стоїть на службах ядра. Із сервера ZP_Research нічого не переноситься: цей
мод стартує порожнім. Конвертер перетворює приклади ZP на конфіги цього мода
(`scripts/convert-zp-examples.py`); два перетворені пакети лежать в `examples/`.

## Що робить

Три речі гри, усі описані JSON адміністратора:

- **Станції.** Покладіть сировину в карго станції й натисніть F. Станція забирає сировину
  й витратні матеріали одразу, працює за календарем (рестарт роботи не губить), викладає
  результат у власне карго й сама починає наступний цикл, поки є сировина. Результат, якому
  не знайшлося місця, лишається записом, доки його не заберуть.
- **Правила.** Який прилад що бере, скільки триває, що виходить і з яким шансом. Зразки
  несуть чистоту; модулі в слотах станції її додають; чистота зразка множить шанс правила,
  яке його з'їдає.
- **Дерево.** Гілки належать фракціям; вузли коштують балів і матеріалів, завершуються
  миттєво або проєктом зі строком і відкриваються батьками (`all` або `any`). Правила
  можуть вимагати вузол; завершений вузол -- факт фракції, а не гравця.

Між ними: **носії** -- предмети, що ховають значення в балах, доки їх не визначити на
терміналі, -- і **предмети даних** зі сталою нагородою. Здача будь-якого з них у термінал
фракції поповнює пул фракції того, хто здає. Станції не платять нічого; платить термінал.

## Фракції і хто тратить

Фракція -- ядрова: угруповання гравця, інакше його базова фракція (одинак -- `loner`,
бандит -- `bandit`, член Долгу -- `duty`). Пул і завершені вузли належать цій фракції.
Тратити може лідер, а також власник поста, названого в налаштуваннях: `ResearchPost` для
угруповань, `BasePost` для базової осі; порожнє ім'я поста означає «ніхто, крім лідера».

Термінали й станції перелічені по фракціях в `OZ_Research_Owners.json`. Якщо хоч одна
фракція перелічила прилади, фракція без переліку не отримує нічого; якщо не перелічив
ніхто, кожен прилад -- усіх.

## Файли

Конфіги живуть у профілі сервера, `$profile:OpenZone\`:

| файл | тримає |
|---|---|
| `OZ_Research_Settings.json` | типовий власник, два імені постів, глибина видимості дерева |
| `OZ_Research_PointTypes.json` | типи балів з категорією, видом і тиром |
| `OZ_Research_Owners.json` | по фракціях: термінали, прилади, тло дерева |
| `OZ_Research_Rules.json` | правила переробки групами |
| `OZ_Research_Tree.json` | гілки з вузлами |
| `OZ_Research_DataItems.json` | предмети даних і їхні нагороди |
| `OZ_Research_Modules.json` | модулі: бонус чистоти й які прилади їх беруть |
| `OZ_Research_SampleTypes.json` | типи зразків і їхні назви |
| `OZ_Research_Statics.json` | стаціонарні станції, які ставляться один раз |

Стан фракції, `research\<фракція>.json`, тримає пул, завершені вузли й поточні проєкти.
`OZ_Research_Statics_State.json` пам'ятає, які статики вже поставлено.

Правка: дев'ять конфігів зареєстровано в редакторі ядра, тож правляться вони у вікні
адміна OpenZone (VPPAdminTools, вкладка CONFIG) з перевіркою й бекапом на кожен запис;
вкладка RESEARCH (склейка `_VPP`) показує фракції з пулами й виконує скидання, нарахування,
завершення й перечитування. Вебредактор у мості Discord -- наступний крок. Назви предметів
беруться з JSON, а не з config.cpp, тож сервер перейменовує зразки й дані без переупаковки.

  VPPAdminTools.
