# Запікання інтерфейсу: від CSS макета до текстур DayZ

*[In English](README.md)*

Вікно дерева досліджень намальоване за HTML-макетом власника, і все, що макет малює CSS
(рамки, корпуси, папір, клапті, шестикутники, кнопки, печатки, рамку кінескопа), у грі має бути
текстурою. Руками це не перемальовують. `bake.py` бере CSS і розмітку кожної картинки, дає
headless Chrome намалювати її на прозорому тлі, вирізає картинки, пакує їх в атлас, пише
`.imageset` і перетворює атлас на `_ca.paa`.

    sprites.json  ->  Chrome малює сторінку  ->  Pillow ріже й пакує  ->  .imageset + _ca.paa

## Набори

Один каталог на набір, у кожному `sprites.json`:

| Каталог | Imageset | Що в ньому |
|---|---|---|
| `common` | `ozl_common` | спільний набір: білі фігури, які тонуються в грі й які може брати будь-який скін -- мітки стану (`mark_lock`, `mark_check`, `mark_dot`, `mark_wait`, `mark_query`), квадратик лінії, вузли зв'язків (`and_square`, `or_diamond`) |
| `ecolog` `clearsky` `duty` `freedom` `sop` `bandit` `neutral` | `ozl_<skin>` | картинки одного вікна фракції. Доки скін не намальовано, його маніфест містить один прозорий спрайт 8x8, `blank`, щоб imageset, який реєструє `config.cpp`, існував |
| `_demo` | -- | приклад кожної можливості маніфесту, запікається лише з `--out` (див. нижче) |

Усі вісім imageset зареєстровано в `OpenZone_Research/config.cpp` (`CfgMods > defs > imageSets`).
Набір, який не зареєстровано, завантажується порожніми картинками без жодної помилки, тому
`bake.py` попереджає, коли запечений ним набір там не згаданий.

## Потрібно

- Python 3.10 або новіший з Pillow 9.1 або новішим, більше нічого
- Node.js 22 або новіший: `shoot.mjs` керує Chrome через вбудований `WebSocket`
- Google Chrome (`C:\Program Files\Google\Chrome\Application\chrome.exe`)
- DayZ Tools: `Bin\ImageToPAA\ImageToPAA.exe`
- шрифти, якими пишуться картинки: системні шрифти Windows за назвою (Arial, Impact, Consolas,
  Courier New, Segoe Print, Ink Free, Bahnschrift, ...) або файл шрифту, названий у
  `@font-face`. Під час запікання мережі немає, тож веб-шрифт через `<link>` (Google Fonts) не
  завантажиться.

Інші шляхи: `--chrome`, `--node`, `--dayz-tools` або змінні середовища `CHROME`, `NODE`,
`DAYZ_TOOLS`.

## Запуск

    python source/ui/bake.py common           # один набір
    python source/ui/bake.py duty freedom     # кілька
    python source/ui/bake.py --all            # кожен набір із sprites.json, крім прикладів з _

Той самий вхід дає ті самі байти: Chrome растеризує програмно, анімації вимкнено, пакувальник
розв'язує нічиї за позицією, а файл переписується, лише якщо його вміст змінився (`.imageset`,
що відрізняється тільки закінченнями рядків CRLF, як у checkout на Windows, вважається
незміненим). Другий запуск нічого не змінює, а `git status` лишається чистим. Це стосується однієї
збірки Chrome: оновлення Chrome може зсунути частину згладжування на кілька рівнів альфи, тож
після оновлення запікання може показати змінені `.paa`. Огляньте їх і закомітьте окремою зміною.

Що пише запуск:

| Файл | Що |
|---|---|
| `OpenZone_Research/gui/imagesets/ozl_<set>.imageset` | опис атласу, `Name "ozl_<set>"` |
| `OpenZone_Research/gui/imagesets/ozl_<set>_ca.paa` | сам атлас, DXT5 |
| `OpenZone_Research/gui/textures/tree/<set>/<name>_ca.paa` | окрема текстура на кожен запис у `textures` |
| `build/ui/<set>/` | поза git: згенеровані сторінки (`sheet.html`), те, що намалював Chrome (`sheet.png`), PNG атласу, зворотне читання кожного `.paa` і `preview.png` |

Маніфест комітять разом з `.imageset` і `.paa`, які він дав.

## Як оглянути результат

Відкрийте `build/ui/<set>/preview.png`: атлас на шахівниці, кожен спрайт обведено й підписано.
`sheet.png` -- сира сторінка, як її намалював Chrome. Журнал запуску звітує по сторінках
(аркуш спрайтів і кожна текстура), по атласу й по кожній текстурі, а не по спрайтах: розмір у
пікселях і діапазон альфи (`alpha 0..255` із багатьма рівнями означає справжню часткову
прозорість); а для кожного `.paa` -- що `ImageToPAA` прочитав його назад як DXT5 з тим самим
розміром і діапазоном альфи. Щоб перевірити один спрайт, знайдіть його в `preview.png`.

## Маніфест

    {
      "scale": 1.5,
      "atlas_max": 2048,
      "gutter": 4,
      "css": ["duty.css", ":root { --ink: #1e1c19; }"],
      "body": { "data-f": "duty" },
      "sprites": [ { "name": "tag", "w": 48, "h": 20, "html": "<div class='tag'>OK</div>" } ],
      "textures": [ { "name": "sheet", "w": 1000, "h": 600, "size": [2048, 1024], "html": "..." } ]
    }

Усі розміри -- в одиницях розкладки: у них міряються розкладки вікна (вікно макета 1600x900).

| Ключ | Типово | Значення |
|---|---|---|
| `scale` | `1.5` | пікселів пристрою на одиницю. Екран власника, 1600 рядків, дає 1,48, тож 1,5 -- це один піксель текстури на піксель екрана. Тримайте однаковим для всього набору |
| `atlas_max` | `2048` | найбільший бік атласу, степінь двійки. Атлас -- найменший прямокутник зі сторонами-степенями двійки, що вміщає всі спрайти; він може бути прямокутним, не лише квадратним |
| `gutter` | `4` | пікселів навколо кожного спрайта, див. «Атлас» |
| `css` | немає | рядок або список. Запис із `{`, `;` чи розривом рядка -- це текст CSS, будь-який інший -- ім'я файлу `.css` у каталозі набору. Його вкладено на сторінку як є, тож CSS макета можна переносити без переписування селекторів. `url(...)` рахується від каталогу набору, не від файлу |
| `body` | немає | атрибути `<body>`. Макет обмежує правила як `body[data-f="duty"] ...`; `"body": {"data-f": "duty"}` робить так, що вони спрацьовують |
| `comment` | -- | ігнорується, примітка для людей (у JSON коментарів немає) |
| `sprites` | обов'язково | картинки атласу, щонайменше одна |
| `textures` | немає | картинки, що отримують власну текстуру |

Спрайт:

| Ключ | Значення |
|---|---|
| `name` | літери, цифри, `_`, починається з літери. Стає іменем зображення в imageset |
| `w`, `h` | проєктна рамка в одиницях |
| `html` | розмітка всередині рамки: рядок або список рядків, який склеюється розривами рядків (так зручніше писати в JSON; одинарні лапки в SVG рятують від екранування) |
| `html_ua` і `html_en` | замість `html`: дві картинки, `name_ua` і `name_en`, див. «Дві мови». Обидва ключі обов'язкові |
| `css` | оголошення й вкладені правила, обмежені рамкою цього спрайта: `"background: #fff; .core { inset: 6px; }"`. Для `@font-face` чи `@keyframes` беріть `css` набору |
| `pad` | одиниць навколо рамки для того, що з неї виступає (відблиск, тінь, повернутий кут) |

Текстура має ті самі ключі без `pad` і з `size`.

### Як виглядає сторінка

Кожна картинка -- вміст рамки `w` x `h` одиниць (`position: absolute`, тож дочірні елементи
можна позиціонувати всередині), яка лежить на `pad` одиниць углиб рамки обрізання. **Усе, що за
рамкою обрізання, відрізається.** Безпосередні дочірні `svg` та `img` мають `display: block`
(рядковий сидів би на базовій лінії тексту й випадав би з малої рамки). Тло сторінки прозоре, а
після CSS набору запікання додає `html, body { background: transparent !important }` і вимикає
анімації й переходи, тож перенесене `body { background: ... }` чи блимаюча мітка не зіпсують
результат. Якщо щось усе ж малює тло, запуск зупиняється з повідомленням «the empty corner of the
page is not transparent».

Усі спрайти набору малюються на одній сторінці (`build/ui/<set>/sheet.html`), тож `id` у розмітці
одного спрайта -- це id усієї сторінки: два спрайти, що обидва задають
`<linearGradient id="g">`, мовчки користувалися б першим із двох. **Починайте кожен id в SVG з
імені його спрайта** (`stamp_uk_noise`, а не `noise`), і варіантам `_ua` та `_en` одного спрайта
теж давайте власні id: це два спрайти на одній сторінці. Запікання зупиняється, коли дві картинки мають
однаковий id. Зарезервовано: `oz0`, `oz1`, ... (`oz<N>`, рамка кожної картинки), `oz-sheet` і
`oz-canary`, а також класи `oz-c` та `oz-s`.

Картинка спрайта має `ceil(w * scale) + 2 * ceil(pad * scale)` пікселів завширшки (так само
заввишки): 24 одиниці -- це 36 px при 1,5. Це і є `Size` в imageset. Якщо є `pad`, показуйте
спрайт у віджеті `w + 2 * pad` на `h + 2 * pad` одиниць, поставленому на `pad` одиниць вище й
лівіше від місця, де має стояти проєктна рамка.

### Атлас

- Картинки пакуються методом MaxRects (best short side fit) у найменший прямокутник зі сторонами-
  степенями двійки до `atlas_max`; `RefSize` -- розмір текстури, а `Pos`/`Size` -- пікселі
  текстури без `gutter`. `Flags 0` і `mpix 0`, як в інших imageset OpenZone.
- Навколо кожного спрайта лежить поле `gutter` пікселів, що повторює крайні пікселі самого
  спрайта, щоб фільтрація в іншому масштабі не підтягла сусіда.
- Пікселі з альфою 0 в межах 4 px від видимого пікселя отримують колір цього пікселя (альфа
  лишається). Chrome пише прозорі пікселі чорними, а фільтрація підмішала б цю чорноту до краю
  білого гліфа темною облямівкою.
- Спрайти малюються на позиціях із цілих пікселів (для 1,5 це кожні 2 CSS px, 3 px пристрою),
  тож край рамки такий самий різкий, де б спрайт не опинився. Растеризатор кривих у Chrome після
  зсуву не зовсім той самий: коло може відрізнятися на кілька рівнів альфи в кількох крайових
  пікселях, коли навколо нього міняється аркуш. Для одного маніфесту результат при кожному
  запуску той самий. `scale`, для якого немає кроку з цілих пікселів (скажімо, 1,37), працює, але
  виводить примітку.
- Якщо спрайти не вміщаються в `atlas_max`, запуск каже про це: великі малюйте текстурами або
  зменшіть `scale`. Бюджет за дизайном: до 2048 x 2048 на атлас скіна і близько 40 МБ `.paa`
  разом; останній рядок запуску показує суму.

### Дві мови

Текст у картинки не йде, окрім стилізованого (печатка, повернутий заголовок, закреслене слово).
Для такого задайте `html_ua` і `html_en`; спрайти будуть `<name>_ua` і `<name>_en`, а який
показати, вирішує stringtable: значення ключа `*_IMG` -- це `set:ozl_<skin> image:<name>_ua` в
українських клітинках (`original` і кожна колонка, що його повторює) і
`set:ozl_<skin> image:<name>_en` в англійській. Обидві картинки малюються в одній рамці, тож
зробіть її достатньо широкою для довшого тексту, а ще вони ділять сторінку, тож їхні id в SVG
мають відрізнятися.

### Окремі текстури

Оздоблення вікна, надто велике для спільного атласу, йде в `textures`. Кожну малюють окремо й
пишуть у `gui/textures/tree/<set>/<name>_ca.paa`: це текстура зі сторонами-степенями двійки (до
4096), яку розкладка вживає як звичайне зображення:

    image0 "OpenZone_Research/gui/textures/tree/duty/sheet_ca.paa"
    mode blend
    "src alpha" 1
    "stretch mode" stretch_w_h

- **З `size`** (`"size": [2048, 1024]`, кожна сторона -- степінь двійки): картинку розтягують на
  все полотно, тож розкладка показує всю текстуру у віджеті `w` x `h` одиниць, і нічого не
  пропадає. Вікно 1600 x 900 не вміщається в 2048 px при 1,5, і 2048 x 1024 -- звичайна відповідь;
  картинку малюють щонайменше в `scale`, а більше, якщо цього вимагає `size`, потім зменшують,
  тож вона лишається різкою.
- **Без `size`**: картинка має `ceil(w * scale)` x `ceil(h * scale)` пікселів і лежить у
  **лівому верхньому** куті наступного полотна зі сторонами-степенями двійки; решта прозора.
  Віджет із `stretch_w_h` показує все полотно разом із прозорою рештою; без `stretch_w_h` він
  показує лівий верхній фрагмент текстури в рідному розмірі (скил dayz-modding, gui-layouts,
  розділ 12), тож видиме залежить від розміру віджета в пікселях, а не від картинки. Так чи
  інакше віджет треба підігнати; віддавайте перевагу `size`. Журнал запуску каже, де закінчується
  вміст.

## Як додати картинки скіна

1. У `source/ui/<skin>/sprites.json` замініть заглушку `blank` спрайтами скіна (скіну зі
   справжніми спрайтами `blank` не потрібен).
2. Перенесіть CSS скіна з макета в `source/ui/<skin>/<skin>.css`, назвіть його в `css` і задайте
   `body`, якщо правила обмежено `body[...]`. Розмітку кожної картинки напишіть у `html`, з id
   в SVG, що починаються з імені спрайта.
3. `python source/ui/bake.py <skin>`, потім огляньте `build/ui/<skin>/preview.png`.
4. Закомітьте маніфест разом з новими `.imageset` і `.paa`.
5. Спрайт у розкладці (або в `LoadImageFile`) -- це `set:ozl_<skin> image:<name>`:

        image0 "set:ozl_common image:mark_lock"
        mode blend
        "src alpha" 1
        color 0.31 0.71 0.91 1

   Фігури з `common` білі, тож колір, у якому вони видні, задає `color` віджета (або `SetColor`
   зі скрипта). Лишайте `mode blend`: рушій не пише в журнал, що його немає (скил dayz-modding,
   gui-layouts, розділ 12).

`source/ui/_demo/` показує кожну можливість: файл CSS поруч із вбудованим CSS, `body`, `css`
спрайта з `pad`, `html_ua` з `html_en` і текстуру з `size` та без нього. Каталог, ім'я якого
починається з підкреслення, -- це приклад: `--all` його оминає, а `--out` потрібен, щоб він не
потрапив у мод:

    python source/ui/bake.py _demo --out build/ui/demo-out

## Тести

    python -m unittest discover -s source/ui -v

Тести охоплюють частини, яким не потрібні ні Chrome, ні DayZ Tools: розтікання кольору (воно не
повинно заносити колір через край спрайта), поле навколо спрайта, пакувальник, правила маніфесту й
id.

## Як працює малювання

`bake.py` пише по одній HTML-сторінці на скін (усі спрайти у відомих прямокутниках) і по одній на
текстуру, а `shoot.mjs` дає headless Chrome намалювати їх через протокол DevTools:
`Emulation.setDefaultBackgroundColorOverride` з альфою 0 для тла,
`Emulation.setDeviceMetricsOverride` для масштабу, `Page.captureScreenshot` з вирізкою. Виміряно:
напівпрозорий квадрат `rgba(255, 0, 0, .5)` виходить як `255, 0, 0, 128`, а порожнє тло -- як
`0, 0, 0, 0`.

Простіше `chrome --headless=new --screenshot --default-background-color=00000000` теж дає прозорий
PNG, але бере перший кадр композитора, який растеризовано лише частково: із захистом від мережі
(див. нижче) сторінка 2400 x 162 px виходила самими верхніми 14 рядками, щоразу. `shoot.mjs`
чекає на шрифти, зображення й два кадри анімації та знімає знову, доки два знімки поспіль не
стануть однаковими. Потім `bake.py` перевіряє, що останній піксель сторінки, піксель-маячок
кольору `1, 2, 3`, на місці; сторінка, намальована лише частково, зупиняє запуск, а не дає
картинку з дірою.

Chrome запускається з `--disable-gpu`, `--disable-lcd-text`, `--font-render-hinting=none` і
`--force-color-profile=srgb`, що робить пікселі однаковими на кожній машині, та з
`--host-resolver-rules="MAP * ~NOTFOUND"`, тож жоден веб-шрифт чи зображення не прийде з мережі.

`ImageToPAA` бере формат з імені джерела: `_ca` -- це DXT5 з альфою, `_co` альфу відкидає.
`bake.py` перетворює PNG з іменем `..._ca.png` у `build/ui/<set>/`, перевіряє код виходу, що
файл існує, непорожній і починається з `05 ff` (DXT5), потім дає інструменту прочитати `.paa`
назад у PNG і порівнює розмір та діапазон альфи з тим, що подали на вхід. Лише тоді файл
копіюється в мод, і то тільки якщо його байти відрізняються від наявних.
